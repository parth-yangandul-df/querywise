The fix:

Both files compile clean. Here's the root cause:

Why IllegalStateChangeError Kept Coming Back
SQLAlchemy AsyncSession is NOT safe for concurrent operations. Even two "independent" SELECT queries can't run concurrently on the same session object. The previous fix only addressed _fetch_tables_by_names — it missed the deeper issue: asyncio.gather was being used with multiple coroutines sharing the same db session.

Two places were broken:

1. schema_linker.py:142
python
# BEFORE — all three use same `db` concurrently
await asyncio.gather(
    _keyword_search_tables(db, connection_id, keywords),
    _column_keyword_search_tables(db, connection_id, keywords),
    _get_tables_by_names(db, connection_id, anchor_table_names),
)
2. context_builder.py:215
python
# BEFORE — both use same `db` concurrently
await asyncio.gather(
    resolve_dictionary(db, column_ids),
    _get_relationships_between(db, table_ids),
)
When two coroutines hit await db.execute(...) on the same session simultaneously, SQLAlchemy's internal state machine corrupts — _connection_for_bind() starts on one coroutine, then close() gets triggered on another, producing:

IllegalStateChangeError: Method 'close()' can't be called here; 
method '_connection_for_bind()' is already in progress
The Fix
Both changed to sequential execution:

python
# schema_linker.py — now sequential
keyword_results = await _keyword_search_tables(db, connection_id, keywords)
column_hit_results = await _column_keyword_search_tables(db, connection_id, keywords)
anchor_results = await _get_tables_by_names(db, connection_id, anchor_table_names)
python
# context_builder.py — now sequential
dictionaries = await resolve_dictionary(db, column_ids)
relationships = await _get_relationships_between(db, table_ids)
The asyncio.gather at lines 156-162 is safe because each call is wrapped in _with_new_session — each gets its own isolated session.

Latency Impact
Minimal. These are lightweight metadata queries (cached tables, dictionary entries). The parallel save was ~20-50ms at best. Eliminating the error is worth far more than that micro-optimization.
